# Отчёт по результатам анализа сетевого трафика

## Executive Summary

В ходе анализа сетевого дампа выявлена критическая ошибка конфигурации: приватный RSA-ключ сервера передаётся по HTTP без аутентификации. 
В связи с использованием TLS без Perfect Forward Secrecy выполнена успешная расшифровка TLS-сессии.

Продемонстрирована полная компрометация конфиденциальности защищённого соединения.

---

## Технические находки

### F-01 — Раскрытие приватного ключа  
Severity: Critical  
CVSS v3.1: 9.8  

Ресурс `/k3y` на порту 1337 предоставляет приватный RSA-ключ в формате PEM по протоколу HTTP без аутентификации.

---

### F-02 — TLS без Perfect Forward Secrecy  
Severity: Critical  

Используется `TLS_RSA_WITH_AES_256_CBC_SHA`.  
Отсутствуют ECDHE/DHE → отсутствует PFS.  
Это позволяет расшифровать TLS-трафик при компрометации ключа.

---

### F-03 — Использование TLS 1.0  
Severity: High  

TLS 1.0 является устаревшим и не соответствует современным требованиям безопасности.

---

## Подтверждение эксплуатации

1. Извлечён приватный ключ.
2. Ключ импортирован в Wireshark.
3. TLS-сессия успешно расшифрована.
4. Получен ресурс `/file` (PNG-файл).
5. Обнаружено секретное сообщение.

---

## Рекомендации

- Немедленно отозвать ключ и перевыпустить сертификат.
- Перейти на TLS 1.2 или TLS 1.3.
- Использовать ECDHE cipher suites.
- Исключить хранение чувствительных данных в web-доступных директориях.
